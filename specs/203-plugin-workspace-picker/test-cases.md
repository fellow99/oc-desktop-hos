## 2. 真机用例（`--inspect` / CDP）

### TC-D1 — 插件在役与四主目录解析

| 项 | 内容 |
|---|---|
| 目的 | 确认插件已加载，且 RPC 返回四个绝对路径 |
| 前置 | 应用已启动；保留 `--inspect` 并完成 `hdc fport tcp:19229 tcp:9229` |
| 步骤 | ① 读 `opencode.log` / hilog 的 `loading plugin` 与 `[oc-desktop]` 主目录记录；② 经 CDP 读 `process.env.OCR_USER_ROOTS`；③ 经 CDP 调 `POST /api/rpc/oc-harmony-workspace-roots/roots`（带应用凭据），打印 `{ output }` |

### TC-D7 — 授权流程

| 项 | 内容 |
|---|---|
| 目的 | 确认授权闭环与事实判据（FR-203-021–025） |
| 前置 | 在系统设置中关闭目标目录的「文件和文件夹」授权（或使用未授权设备） |
| 步骤 | ① 切到该 Tab，记录 UI 表现与日志；② 若出现「请求授权」，点击并记录 ArkTS 回调码；③ 无论回调结果，观察是否**重试列举**并以列举结果为准；④ 检查「去系统设置」入口是否可点且落到本应用信息页；⑤ 在系统设置中开启授权后返回并手动「重试」 |
| 期望 | 未授权 → 对话框内可见授权动作或明确归因；授权成功（系统开关已开）→ **列举成功**即渲染；失败/拒绝 → 原因 + 「去系统设置」；**MUST NOT** 只显示 `EACCES` |
| 覆盖 | AC-6 |
| 备注 | 🔶 若本 runtime 复现「回调 0 但无弹窗、访问仍失败」，即为沿用结论 F8 的复现 —— 必须原样登记并验证「去系统设置」兜底路径可用 |
