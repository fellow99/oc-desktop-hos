## 1. 目的

鸿蒙（HarmonyOS）设备**没有 `git`**：toybox 不提供，系统 `PATH` 里也没有任何等价物（能力清单 v2.0.26 §11 G9）。因此本应用**今天无法完成任何版本控制操作** —— 即使工作区里就有一个 git 仓库：上游 `opencode.vcs.git` 走 `gitExecutable` + 子进程，必然失败（真机日志已出现 `worktree discovery failed … strategy=git`）。

本需求交付一个 `oc-desktop-hos` 专用 opencode 插件 `oc-plugin-git`：把**纯 JS 的 git 实现 isomorphic-git** 嵌入应用，提供

1. **21 个 git 工具**（模型可在对话里直接完成 clone / 提交 / 分支 / 推送等）；
2. **「Git 凭据」设置页**（用户为带账号仓库录入用户名/口令；口令只落设备侧文件，不进对话）；
3. **VCS provider 覆盖**（用同一套 JS 实现在无 `git` 设备上重新点亮应用自带的**文件状态 / 分支 / 差异**界面）。

全部发生在设备侧进程内：不依赖外部二进制、不依赖原生模块、不触碰父工程。

**范围外（明确不做）**：

- `rebase`：isomorphic-git **无此原语**（`Object.keys(require('isomorphic-git'))` 74 项零命中，见 F7），自研等于重写提交重放引擎；
- `blame` / `grep`（`grep` 已有 `oc-plugin-harmony-search` 的纯 JS 实现）/ `show --stat` 之外的富文本渲染 / 子模块（`submodule`）/ `worktree` / `LFS`；
- SSH 传输：isomorphic-git **没有 SSH 客户端**（F11），只能 HTTPS Basic 认证；
- SHA-256 仓库（isomorphic-git 现状只支持 SHA-1）；
- 运行时按需安装依赖（v1 立场 `L1 仅本地`，依赖必须构建期预置，`plugins/README.md` §2）；
- 父工程改动（插件 / 补丁 / 脚本 / 规格全部落在 `oc-desktop-hos`，见 D13）。

## 3. 关键事实

| # | 事实 | 含义 |
|---|---|---|
| F1 | isomorphic-git 是**纯 JS**（无 `.node`、无 spawn），发布物把 11 个依赖标为 external | 依赖必须随包供给（不可指望宿主闭包） |
| F2 | 依赖实测：`isomorphic-git@1.44.2` 闭包 = **55 包 / 8.4 MB**；追加 `diff@9.0.0`（**零依赖**）= **56 包 / 9.3 MB** | `dsh-dist` 等价物（本工程 resfile + 设备解压产物）增量约 9.3 MB，可接受 |
| F3 | 本机 PoC（Node 24 / Windows，`isomorphic-git@1.44.2`）：`init`+`add`+`commit` **65–71 ms** 成功；`statusMatrix` 正确；`listServerRefs`（公开仓库）**1.08 s / 133 个分支**；`depth:1` 浅克隆 **3.3 s / 43 文件** | 库在 Node 上可用；`http/node` 传输路径成立（**设备侧仍需实测**，见 §21） |
| F4 | 本机 PoC：`github.com` **超时**，`gitlab.com` / `gitee.com` 可达；dsh 真机记录同一现象 | 无账号用例必须允许「原地址失败 → 换可达等价仓库并如实记录」（D4） |
| F5 | isomorphic-git **没有** `diff` / `show` / `revert` / `rebase` / `blame` / `grep`；`cherryPick` **无** `reversal` 参数 | `show`/`revert` 自建；`diff` 用 jsdiff；`rebase` 明确不交付 |
| F6 | `onAuth({url})` 只做 **HTTPS Basic**，可返回 `{username,password}` / `{headers}` / `{cancel:true}`；`onAuthFailure` 可拒绝 | 凭据注入点明确，且**只在服务端要求认证时**触发 |
| F7 | `isomorphic-git` 导出 74 项（本机 `Object.keys` 实测），含 `stash` / `cherryPick` / `merge` / `fastForward` / `findMergeBase` / `isDescendent` / `listServerRefs` / `getRemoteInfo2` / `hashBlob` | 工具面可覆盖 dsh 已验证的 21 项 |
| F8 | **promise 方言硬契约**：isomorphic-git 用 `isPromiseFs()` 无参调用 `fs.readFile()` 探测；适配器**同步抛错**即被判成 callback 风格 ⇒ 11 个命令全部永久挂起（dsh 真机事例：工具 `ToolOutcomeUnknownError`、会话卡死） | 适配器每个方法**必须声明 `async`**（含 `rm`），这条要写成契约测试 |
| F9 | 上游 `VcsDefinition` 契约：`init` / `info` / `base?` / `branches` / `status` / `diff`；`Info = { provider?, branch: { current?, default? } }`；`BranchList = string[]`；`FileStatus = { file, additions, deletions, status: added|deleted|modified }`；`diff` 返回 `FileDiff.Info[]`（含 `patch` 文本） | §12 的覆盖面据此实现；`base` 缺失时上游按默认分支兜底 |
| F10 | 上游对 provider 异常是**吞掉并记录 warning**（`protect` / `review`），返回回退值 | 我们的 provider 出错**不会崩 UI**，但也**不会显眼** ⇒ 必须自带 `console.log` 诊断行（落 hilog） |
| F11 | isomorphic-git 无 SSH：`git@host:path` 会被改写成 `https://host/path`（丢弃用户名） | 只能用 HTTPS + 用户名/口令；`git@` 风格地址必须显式改写说明 |
| F12 | 设备 `symlink` 不可用（`EACCES`），`hmdfs` 大小写不敏感、无硬链接 | 适配器不做软链语义；同目录大小写冲突只能如实报错 |
| F13 | `statusMatrix` / `isIgnored` / `readBlob` / `readTree` / `resolveRef` 等只读原语足够支撑 `status`/`diff`/`show` | 无需额外索引或缓存层 |
| F14 | 上游 `Vcs.Mode` 三值：`working` / `branch` / `committed` | `diff` 需分别实现 HEAD↔工作区、merge-base↔HEAD、base↔HEAD 三类比较 |

## 4. 用户故事

- 作为用户，我希望在对话里让模型**克隆并读懂**一个公开仓库，不必先想办法装 git。
- 作为用户，我希望能为**带账号仓库**在设置页填一次用户名/口令，之后模型执行 pull / push 不需要知道口令。
- 作为用户，我希望应用自带的**变更列表 / 分支 / 差异**界面在有 `.git` 的目录里重新工作（今天它是坏的）。
- 作为用户，我希望模型**只在当前工作区内**读写：越界必须明确拒绝，不得静默改到别处。
- 作为用户，我希望任何失败都**如实说明原因**（缺凭据 / 认证被拒 / 冲突 / 越界 / 网络不可达），而不是假装成功或无限重试。
- 作为用户，我希望知道哪些 git 能力**本平台做不到**（`rebase`、SSH、SHA-256 仓库），而不是被静默降级。

## 6. 方案对比

### 6.1 依赖供给 + 文件访问（主方案轴）

| | **A. 构建期物化依赖 + 插件内 chroot 适配器（采用）** | B. 走上游文件 API（`fs/list` / `experimental/fs/write` 等） | C. 预打包成单文件 vendored bundle 入库 |
|---|---|---|---|
| 依赖供给 | `collect-app.mjs` 新增 `collectPluginRuntime()`：npm 拉取 → 复制到 `resfile/.../plugins/oc-plugin-git/node_modules/` | 同 A | esbuild/rollup 生成物入库 |
| 文件访问 | 插件内 `node:fs/promises`，仓库根 chroot | 逐次经上游 RPC（进程内 `Effect` 调用），每次要过 `FileAccess` 校验 | 同 A |
| 原子写 / `rename` / `mkdir` / `chmod` | 直给（POSIX） | **缺失**（上游协议无 `mkdir`/`rename`/`chmod`）⇒ 无法实现 clone/commit | 同 A |
| 性能 | 好（chroot 内直连 node:fs） | 差（clone 上万次调用，每次跨层校验 + Effect 调度） | 好 |
| 新增上游改动 | 0 | 需新增多个文件 API（协议 + codegen） | 0 |
| 约定符合度 | 符合（生成物不入库） | 大幅扩大上游面 | **违反**「生成物不入库」（`plugins/README.md` §3） |

**结论：采用 A。** B 在 `mkdir`/`rename`/`chmod` 上直接不可行（git 的对象/索引写入依赖它们），C 违反工程约定且升级要重打包。

**方案内被否决的子选项**：曾考虑把 isomorphic-git 闭包放在**插件目录之外**（如 `resfile/.../git-runtime/`）再由插件按绝对路径 `import()`。否决理由：多一处版本真值、多一段 `main.js` 复制逻辑、且插件目录方案已被 `materializePlugins()` 的 `cpSync` 天然覆盖（现状 #7）。

### 6.2 凭据入口

| | **A. 设置页 + 插件 RPC（采用）** | B. 模型工具录入（`git_credential_set`） | C. 纯文件、无 UI |
|---|---|---|---|
| 口令是否进对话 | **否** | **是**（进入会话记录与 DB） | 否 |
| 设备上可操作性 | 真实可用（设置页） | 可用但危险 | **不可用**（应用私有目录，用户无法写文件） |
| 工作量 | 1 个 UI 补丁 + 4 个 RPC 方法 | 1 个工具 | 0 |
| 安全结论 | 可接受（`0600` + 永不回显） | 不可接受（dsh 已明确否决） | 无法交付 |

**结论：采用 A**，C 作为降级路径记录（若补丁因上游漂移无法落地，功能链仍可经 `--inspect` 写入凭据文件完成验收，但**不作为交付形态**）。

### 6.3 VCS 覆盖 vs 仅工具

| | **A. 同时覆盖 VCS provider（采用）** | B. 只交付工具 |
|---|---|---|
| 自带 diff/分支 UI | 恢复可用 | 继续降级 |
| 额外成本 | `lib/vcs.js`（约 5 个方法，复用同一适配器与 diff 能力） | 0 |
| 风险 | 覆盖语义依赖 `Map.set`（F: 现状 #4/#5），需真机验证；失败则退化为 B | 无 |

**结论：采用 A**，并把「覆盖是否生效」做成**独立验收项 + 可回退点**（§12.4）。若真机证明覆盖不生效或引起 UI 异常，**当场把 `lib/vcs.js` 的注册注释掉即可回到 B**，不影响 21 个工具。

### 7.1 组件总览


### 7.3 依赖物化（唯一新增构建步骤）

`collect-app.mjs` 新增 `collectPluginRuntime()`，形状照 `build-opencode.mjs` 的既有 npm 步骤：

- 常量 pin：`ISOMORPHIC_GIT_VERSION = '1.44.2'`、`JSDIFF_VERSION = '9.0.0'`。
- 在**构建机临时 staging 目录**（`os.tmpdir()` 下，构建结束即清理）`npm install --omit=dev --no-audit --no-fund isomorphic-git@1.44.2 diff@9.0.0`。
- 把 `node_modules/` 整棵复制到 `web_engine/src/main/resources/resfile/resources/app/plugins/oc-plugin-git/node_modules/`（**仅目的地**，不入库）。
- 顺序固定：`discoverPlugins → 静态断言 → 投放源码 → collectPluginRuntime() → 产物断言`（源码投放会先 `removeTree` 目标目录，因此物化必须在其后）。
- 断言（任一不满足即抛错、不静默）：`isomorphic-git/package.json` 版本 == pin；`isomorphic-git/http/node` 入口存在；`diff/package.json` 版本 == pin；包数 56 ± 0；总体积 ≤ 12 MB；`findFiles` 抽样不含 `.node` / `.so`。
- 幂等：目标已存在且两份版本号一致 → 快路径跳过（`--force-plugin-runtime` 可强制重建）。
- `collect-app.mjs --check-only` 跳过物化（只跑静态断言），便于快速回归。

> **为什么落在插件自己的 `node_modules/`**：现状 #7 的 `cpSync` 只复制**插件目录**，落在别处（如 resfile 顶层）不会被带到设备配置文件目录；而现状 #6 的 Node 裸包解析会先查插件目录下的 `node_modules/`。两者叠起来，插件目录内嵌套是唯一「复制得走 + 解析得到」的位置。

## 8. 仓库根围栏（安全属性）

围栏决策点是**仓库根**，这是安全属性而非待修缺陷：

1. **根的唯一来源**：`context.location.project.directory`（项目根，绝对路径，`fs` 已由宿主规范化）。
2. **工具参数 `dir`**：可选，相对 `context.location.directory`（会话目录）解析；缺省 = 会话目录；解析后必须**落在项目根内**（`root === target` 或 `target.startsWith(root + sep)`），否则 `git_*: path is outside the workspace root …`。
3. **适配器内每个路径**：`join(root, rel)` → `normalize` → 前缀包含校验；`..` 逃逸 / 绝对路径 / 软链指向根外一律拒绝，**不落到 `node:fs`**。
4. **无提权通道**：本壳没有 dsh 的一次性提权 + 审批面板（现状 #16），因此**不做**「申请提权后放行」，而是**明确拒绝并提示**（把项目根换成目标目录，或用「打开项目」把该目录作为工作区）。
5. **如实披露的取舍**：git 仓库**内部**写入（`.git/objects`、索引、工作区检出）不逐次经过上游 `FileAccess` 校验，围栏收窄为「仓库根」单点。这与 `oc-plugin-harmony-shell`（常驻 shell 可执行任意命令，工具层围栏而非沙箱，`plugins/README.md` §5 已披露）同级，且**更严**（shell 无路径围栏）。

## 9. 凭据流程

### 9.1 文件形态（git 原生）

- **路径**：`~/.git-credentials`；设备上 `HOME` 已被改写（现状 #14），实际为 `<userData>/.git-credentials` = `/data/storage/el2/base/files/.git-credentials`。
- **格式**：**与 `git credential-store` 同形** —— 一行一条带 userinfo 的 URL：`<协议>://<用户名>:<口令>@<主机>[:<端口>][/路径]`，userinfo 两段做**百分号编码**（口令含 `:` `@` `/` 可原样往返）。
- **权限**：强制 `0600`（每次写入经「临时文件 + `rename`」原子替换，权限随之收回）。
- **解析容忍**：空行、`#` 注释、非 URL 行、无 userinfo 行一律跳过而不抛错（手工编辑不该让所有 git 操作失败）。
- **匹配**：协议与 `host[:port]` 必须一致（大小写不敏感）；**带路径的行按前缀匹配并优先于裸主机行**；同分时**文件里靠后的行覆盖靠前的**（与 git 的「后来记录覆盖」一致）。

### 9.2 为什么只有一处真值

dsh 版是「凭据库优先 + 文件镜像」的两处真值（受其 `ctx.credentials` 面与设置页限制）。本工程**没有**可复用的 git 凭据库（上游 `Credential` 是 provider/integration 维度、落在 SQLite），因此**只保留文件一处**：

- 设置页的保存/删除**直接写该文件**（经插件 RPC）；
- `auth.js` 只读该文件；
- 好处：单一真值、无镜像时序、无「保存后文件里还没有」的时间窗；
- 代价（如实登记，见 §19 L4）：文件在应用私有目录，**外部工具无法直接复用**；本设备也没有外部 `git`，故无复用需求。

### 9.3 运行期流程

```
git 操作需要认证（服务端返回 401/403/404 且未带凭据）
         │
         ▼
auth.js：从目标 URL 取 协议 + host[:port] → credentials.match()
         │
     命中 ──► onAuth 返回 { username, password }   // 明文只在进程内存
         │
     未命中 ──► onAuth 返回 { cancel: true }
                → 工具报错（可照抄）：
                  「该主机没有配置凭据：请在 设置 → Git 里添加
                    <协议>://<用户名>:<口令>@<主机>:<端口>
                    或直接编辑 ~/.git-credentials（0600）。」
                （**不把裸 401/404 抛给模型**；不猜测、不匿名重试）
         │
onAuthFailure ──► 报「凭据被拒绝」并点名主机（不回显口令），最多重试 1 次
```

- 明文**进不了**对话、日志、`opencode.json`：工具参数里没有凭据字段；插件只经凭据文件读取。
- 无账号仓库从不触发 `onAuth`，零凭据可完成 clone / fetch / pull 与全部本地操作。
- 日志纪律：任何诊断输出对凭据只打印 `host` 与 `passwordLength`，**绝不打印值**。

### 9.4 设置页（补丁 0008）与 RPC 契约

`rpcID = "oc-harmony-git"`；所有方法**不抛错**，统一返回结构化结果；handler **必须 async**（现状 #11）。

| 方法 | 输入 | 输出 | 语义 |
|---|---|---|---|
| `credentials.describe` | `{}` | `{ path, exists, mode, count, message }` | 供页面自门控与诊断；`mode` 为八进制字符串（`"600"`） |
| `credentials.list` | `{}` | `{ path, entries: [{ protocol, host, username, passwordLength }] }` | **永不回传口令**；`passwordLength` 供「已配置」提示 |
| `credentials.save` | `{ protocol?, host, username, password }` | `{ ok, code, message, path }` | `protocol` 缺省 `https`；同 `协议+host+用户名` 视为同一条（替换而非追加） |
| `credentials.remove` | `{ protocol?, host, username }` | `{ ok, code, message }` | 只删匹配行；删空则删文件本身 |

`code ∈ ok | invalid-host | invalid-username | invalid-password | invalid-protocol | write-failed | not-found`。

页面行为（补丁侧）：

- 新设置页 **Git**（`SettingsRootTab` 增加 `git`，图标 `branch`，`pageIcons` / `pageLabels` 同步，i18n `en.ts` / `zh.ts` 加键）；

## 11. 三个自建能力（isomorphic-git 缺口，F5）

### 11.1 `show`

`readCommit` / `readTree` / `readBlob` / `readTag` 拼装：提交元信息（作者、时间、parents、message）+ 变更清单（父提交 tree ↔ 本提交 tree 的路径差）+ 逐 blob 内容（超过阈值截断并显式说明）。无新依赖。

### 11.2 `diff`

`statusMatrix` 给变动清单 → `readBlob` 取两侧字节 → jsdiff `createTwoFilesPatch` 产出标准 unified diff。

- `stat` 模式：只汇总新增/删除行数；
- `pathspec` 过滤：只对匹配路径取 blob；
- **二进制检测**：含 NUL 字节即判二进制，输出 `Binary files a/… and b/… differ`，**不做文本 diff**；
- 上限：单文件 256 KiB、单次总量 1 MiB（超出即截断并标注，不静默丢）。

### 11.3 `revert`（自建，fail-closed）

`cherryPick` **没有** `reversal`（F5），按以下算法：

1. `readCommit({ oid })`；**恰好 1 个父提交**才继续，否则明确拒绝（不做合并提交的反向）。
2. 枚举父提交与目标提交之间的变更路径（两棵 tree 对比）。
3. 对每个变更路径：把**父提交**的内容物化到工作区（父无此路径 → 删除该文件）。
4. `add` 上述路径 → `commit`（消息模板 `Revert "<原提交标题>"`）。

**冲突语义（fail-closed）**：第 3 步前先比对工作区该路径的 blob oid 与目标提交是否一致；不一致 ⇒ 拒绝执行并列出冲突路径，**绝不静默覆盖用户改动**。

## 12. VCS provider 覆盖

### 12.1 为什么可行

- 内置 provider 以 `id: "git"` 注册（现状 #4），`VcsEditor.add` 是 `Map.set` ⇒ **同 id 后注册者胜**；
- 插件激活在 `internal.pre` **之后**（现状 #5）⇒ 我们的注册晚于内置；
- 覆盖后无需任何上游改动；表单/差异视图仍走上游既有渲染管线。

### 12.2 契约实现（`lib/vcs.js`）

| 方法 | 实现 | 说明 |
|---|---|---|
| `init` | `git.init({ defaultBranch })` | 上游「新建仓库/初始化」路径会调它 |
| `info` | `currentBranch` + 默认分支推断（`init.defaultBranch` 配置 → `main` → `master` → 第一条分支） | 返回 `{ branch: { current, default } }` |
| `base` | 默认分支的 `ref`；`{ name, ref, source: "default" }` | 供 `branch` 模式的比较基线 |
| `branches` | `listBranches`（支持 `search` / `limit`） | 返回 `string[]` |
| `status` | `statusMatrix` → `FileStatus[]`（`additions` / `deletions` 由 §11.2 统计）；无 HEAD 时按 untracked 处理 | 与上游同语义 |
| `diff` | `working` → HEAD↔工作区；`branch` → base↔HEAD；`committed` → base↔HEAD（无 base 时返回空） | 每文件产出 `patch` 文本 + 统计，遵守单文件/总量上限 |

### 12.3 启动诊断（must-have）

`setup()` 成功注册后打印一行（落 hilog，前缀 `[oc-desktop]`）：

```
[oc-desktop] plugin oc-harmony-git: tools=21 vcsProvider=git(override) credentials=<path>
```

失败路径必须显式：`context.vcs.transform` 缺失 ⇒ 抛错（插件 `failed`），不静默降级；工具与 VCS 分别 try/catch，**工具注册失败不连带 VCS**，反之亦然，各自把原因写进日志。

### 12.4 回退点

若真机证明覆盖引起 UI 异常（例如上游对 `base` 的期望不同），**只注释 §12 的注册调用**即可回到「仅工具」形态，验收标准 AC-6 相应降级为「记录为未交付」。

## 14. 错误处理

| 场景 | 表现 |
|---|---|
| 目标目录不是仓库 | 明确报「不是 git 仓库」并给 `git_init` / `git_clone` 建议，**不静默创建** |
| `dir` 越出项目根 | `git_*: path is outside the workspace root (<root>)`，并提示换项目根（无提权通道） |
| 缺凭据 | §9.3：点名主机、设置入口与文件路径，附可照抄的占位行；**不抛裸 401/404** |
| 凭据被拒 | 报「凭据被拒绝」+ 主机（不回显口令），最多重试 1 次 |
| 合并 / 摘取冲突 | 默认 `abortOnConflict`，报冲突路径，工作区不被污染；提示可用 `git_merge` 中止 |
| `revert` 工作区分叉 | §11.3 fail-closed 拒绝并列出冲突路径 |
| 网络不可达 / DNS 失败 | 报主机名 + 底层错误（如 `Request timed out`），不假装成功；给 `depth` / `singleBranch` 建议 |
| 远端拒绝推送 | 原样上报服务端答复（如 `pre-receive hook declined` / non-fast-forward），**不自动 force** |
| clone 体积 / 耗时 | 报已用时与建议；`signal` 透传给 isomorphic-git（工具取消 → 停止） |
| 调用被取消 | 交由上游注册表处理取消语义，不当作失败报告 |
| `rebase` 请求 | 明确「本平台不支持 `rebase`（上游库无此原语）」，不静默用 merge 冒充 |
| 第三方依赖缺失 / 版本不符 | 启动诊断 + 工具调用报「git 运行时缺失（期望 isomorphic-git@1.44.2）」；构建期已断言，属双保险 |
| VCS provider 内部异常 | 上游 `protect` 会吞掉并回退（F10）⇒ 我方在 catch 里 `console.log` 归因行，便于 hilog 取证 |


**错误上报口径（工具层）**：**可归因的预期失败**（缺凭据 / 越界 / 不是仓库 / 冲突 / 服务端拒绝）以**返回值** `{ content: "<工具名>: <原因与下一步>" }` 上报 —— 模型能读到完整原因并自行改正，步骤不会因此终结；**意外异常**（编程错误、适配器缺陷）直接 `throw`，由上游包成 `Tool.Error`。两者都不允许出现「静默成功」或「空结果」。

## 19. 约束与已知限制

- **L1 `rebase` 不支持**：isomorphic-git 无此原语（F5）；工具面不含它，被问到时明确说明，不静默用 merge 冒充。
- **L2 无 SSH**：只能 HTTPS 用户名/口令；`git@host:path` / `ssh://` 会被库改写为 `https://`（丢用户名），需配 https 凭据（F11）。
- **L3 体积**：resfile 与设备解压产物增加 **≈ 9.3 MB**（56 包）。
- **L4 凭据文件在应用私有目录**：`~/.git-credentials` 位于 `<userData>`，外部工具不可读、用户不能用文件管理器直接编辑；**页面是唯一入口**（dsh 的「外部 git 复用」诉求在本设备不成立：设备没有 git）。
- **L5 围栏粒度**：仓库内部写入不经上游逐次 `FileAccess` 校验（§8-5）。
- **L6 无审批交互**：缺凭据只给指引，不弹「运行时索要口令」的对话框（上游无该交互面）。
- **L7 哈希算法**：仅 SHA-1 仓库；SHA-256 仓库不在范围。
- **L8 二进制差异**：只报 `differ`，不出内容级 diff（§11.2）。
- **L9 VCS 覆盖依赖 `Map.set` 语义**：上游若改为「禁止同 id 覆盖」，覆盖会静默失效 ⇒ 靠启动诊断行 + AC-6 暴露（回退点 §12.4）。
- **L10 纯 JS 性能**：clone 大仓库明显慢于原生 git（`depth` / `singleBranch` / `noTags` 缓解，不改变量级）。
- **L11 hmfs 语义**：大小写不敏感、无硬链接/软链；同名不同大小写文件可能冲突，失败如实报错。

## 20. 风险与遗留

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | **设备网络可达性**：`github.com` 在同类设备/本机均超时（F4） | 无账号用例可能无法按原地址执行 | D4：改可达等价仓库并如实记录；不带病修改代码 |
| R2 | 依赖物化需联网（npm registry） | 构建机离线时失败 | 失败即抛错（不静默产出空包）；文档记录离线时的预置路径 |
| R3 | 纯 JS clone 大仓库超时 / 内存峰值 | 操作失败或主进程卡顿 | `depth`/`singleBranch` 暴露；`signal` 透传；作为真机观察项 |
| R4 | **promise 方言坑**（F8）：适配器同步抛错 ⇒ 全部 git 调用永久挂起 | 会话卡死、表现为「工具结果未知」 | 适配器全 `async` + 契约单测（断言 `constructor.name === 'AsyncFunction'`）+ 复刻 `isPromiseFs` 探测 |
| R5 | VCS 覆盖与内置 provider 冲突（同 id） | 覆盖失效或 UI 异常 | 启动诊断行 + AC-6；回退点 §12.4 |
| R6 | 上游对 provider 异常静默（F10） | 问题不显眼 | 我方 catch 里 `console.log` 归因；hilog 取证 |
| R7 | **内网仓库是明文 `http://`** | Basic 凭据明文过网 | 如实登记（§18.2 注）；建议生产改 HTTPS；不做额外持久化 |
| R8 | 上游升级（v2.0.27+）改变 `VcsDefinition` / `Editor` / 插件 source 契约 | 覆盖或工具注册失效 | pin 版本常量 + 装载断言；升级时复跑 AC-1/AC-2/AC-6 |
| R9 | UI 补丁（0008）与上游 `settings` 结构漂移 | 补丁 `apply` 失败 | 补丁独立成一条、可单测 `apply --reverse --check`；漂移即修 |
| R10 | 默认身份占位符被推入共享仓库（若做 AW-6） | 共享历史出现 `yourname` | 默认不做 AW-6；如要做，先 `git_config` 设真实身份并当轮点名 |
| R11 | `collect-app.mjs` 期望工具表未同步 | 构建期失败（fail-visible，非静默） | 落点 8 明确要求同步；AC-12 覆盖 |
| R12 | `--inspect` 触达不到插件 `ctx`（无全局句柄） | 运行期自证只能靠插件日志 | 启动诊断行 + 工具返回值 + `/api/plugin` inventory；探针走 CDP 主进程 `fetch`/`fs` |
