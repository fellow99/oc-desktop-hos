## 1. 目的

在「打开项目 / 选择工作区目录」对话框的顶部提供**四个主目录**（沙箱 / 桌面 / 文档 / 下载），
使用户能在**已授权的用户目录**里浏览、新建文件夹并选定目录，把该目录注册为 opencode 项目根。

当前对话框只能从沙箱（`HOME` 被重定向后的 `userData`）出发浏览，用户目录里的文件夹无法被选为工作区，
已授权的用户目录能力无法从该入口被使用。真机已登记该缺口：

- **✅ 实测** `打开项目` 只能「选定预填路径」，不能「浏览」；目录浏览不可用的直接原因是搜索/建议通道
  `GET /api/fs/find` → 500 `unsupported platform for ripgrep`（`docs/鸿蒙环境能力清单-v2.0.26.md` §11.4-2 / §6 G2）。
- **✅ 实测** 对话框预填 `<userData>/workspace` 且「选择文件夹」可成功 ⇒ **列举通道本身可用**（§11.4-2）。

因此本模块不是「造一个浏览能力」，而是：**给已有对话框补上「四个主目录」的入口与边界**，
并把「目录枚举」与「权限」两条只有主进程/ArkTS 侧才具备的能力，经**壳专用 opencode 插件**暴露给渲染层。

## 3. 关键事实

| # | 事实 | 含义 |
|---|---|---|
| F1 | 渲染层恒为 `platform === "web"` ⇒ 恒定走应用内 `DirectoryPickerDialog` | 替换点在 `packages/app/src/workspaces/selection/`，**必须打补丁**；不需要动 desktop 平台臂 |
| F2 | `fs/list` 接受绝对路径且不限制根 | 四主目录的列举**复用现有原语**，不自实现文件系统；根围栏只能在 UI 层落实（本设计的选择，见 §8） |
| F3 | `fs/find`（搜索/建议）在目标平台不可用 | 四主目录模式下**不依赖**建议通道；退化为「逐级展开」是预期路径 |
| F4 | 上游插件无 UI 钩子，但有 **RPC** 钩子且无需生成代码 | 「能力」这一半用**插件机制**（`context.rpc.register`）实现；「UI」这一半用**最小上游补丁**。这正是本需求「尽量使用插件机制，不行再打补丁」的落点 |
| F5 | 插件运行在**服务端进程**＝`inprocess` 形态下的 Electron 主进程 | 插件可直接读 `process.env`、用 `node:fs`，并经 `createRequire` 拿到 `electron` 的 `systemPreferences`（权限桥）；**这是渲染层做不到的** |
| F6 | 主进程启动时 `process.env.HOME` 仍是真实家目录（`/storage/Users/currentUser`），重定向发生在其后 | 三个用户目录可在**覆盖 HOME 之前**捕获并落成绝对路径，不需要 ArkTS 侧补实现（F5/`#12`）；`ContextPathAdapter.getUser*Dir` 的空实现**不作为依赖** |
| F7 | 三个用户目录未授权时 `EACCES`/`EPERM`；`Desktop` 为 `system_basic`（需 ACL），`Documents`/`Download` 为 `normal` | OS 层授权前提是 `006-signing-identity` 已声明的三项权限；本模块**只消费**，不自行声明 |
| F8 | **同类工程真机结论（🔶 沿用，本工程未复现）**：在 PC 模式 runtime 上，`RequestPermissionCode` 对 `directory_desktop/document/download` **返回 `0` 但不弹窗、也不改变实际访问**；`CheckPermissions` **即使系统开关已打开仍返回 `false`**；唯一生效面是「设置 → 文件和文件夹」 | 授权判定**不得只依赖 check 桥**：授权成功后必须**以一次全新的 `fs/list` 是否成功**作为事实判据（`dsh-desktop-hos/plugins/harmony-plugin-workspace-picker/README.md`「真机实测」） |
| F9 | 品牌化后置断言（37 项，含引用点漂移守卫）对 `app-archive.bin` 硬校验 | 改动 `packages/app` **必须**同时核对 `scripts/verify-branding.mjs` 的既有断言不被触发；新增用户可见文案不得出现禁用词与 `OpenCode` 指称 |

## 4. 用户故事

- 作为用户，我希望在「打开项目」对话框顶部切换到桌面 / 文档 / 下载，以便把这些已授权目录中的文件夹注册为项目。
- 作为用户，我希望选定主目录后能逐级进入子文件夹、在其中新建文件夹并选中，以便精确指定项目位置。
- 作为用户，当某个用户目录尚未授权时，我希望在对话框内直接完成授权并继续，不必自己去找系统设置。
- 作为用户，我希望下次打开对话框时默认停留在上次使用的主目录，减少重复切换。
- 作为排障者，我希望从 hilog 与 `--inspect` 即可确认四主目录路径解析、插件激活与 RPC 在役。

## 5. 功能需求

### FR-1 主目录切换

- FR-1.1 对话框顶部渲染四个主目录 Tab：**沙箱 / 桌面 / 文档 / 下载**。
- FR-1.2 切换主目录时：浏览视图重置为该主目录根、清空选中、重新列目录。
- FR-1.3 默认主目录取上次使用值（FR-7）；首次使用默认为「沙箱」。
- FR-1.4 仅当四主目录能力**可用**时进入「四主目录模式」；能力不可用（插件未激活 / RPC 未注册 / 非本壳）
  时 MUST 完整回退为上游对话框行为，MUST NOT 出现半残状态（自门控，见 FR-8.4）。

### FR-2 主目录解析

> 路径解析只在**服务端/主进程**成立（渲染层看不到 `APP_HOME`，也看不到真实家目录），故经插件 RPC 返回。

- FR-2.1 沙箱主目录 = `path.join(app.getPath('userData'), 'workspace')`（真机 `/data/storage/el2/base/files/workspace`）；
  解析时 MUST 检查存在性，不存在则 `mkdirSync(recursive)` 自动创建。
- FR-2.2 桌面 / 文档 / 下载 = `<真实家目录>/{Desktop,Documents,Download}`；真实家目录在 `HOME` 被改写**之前**捕获。
- FR-2.3 每个用户目录 MUST 逐个做「存在且是目录」校验；不满足则该主目录标记为**不可用**（`available: false` + `reason`），
  仍出现在 Tab 中但内容区显示不可用说明与重试入口；MUST NOT 静默换根、MUST NOT 回退到其它主目录。
- FR-2.4 解析结果 MUST 记录进 `[oc-desktop]` 结构化日志（id / 绝对路径 / 可用性 / 时间戳），供真机取证。

### FR-3 目录浏览

- FR-3.1 沿用既有树形浏览器（逐级展开）；只列目录、名称排序。
- FR-3.2 只渲染**非隐藏**条目（宿主标记的 hidden 项不渲染）；**不提供**「显示隐藏文件」开关。
- FR-3.3 浏览域被锁定在选定主目录内：导航（展开、面包屑/「上级」）MUST NOT 上行到主目录根之上（§8 根围栏）。
- FR-3.4 四主目录模式下 MUST 移除手动路径输入（path TextInput 与建议浮层）：UI 中不存在提交任意绝对路径的入口。
- FR-3.5 `fs/list` 返回的截断/超限情形 MUST 就地可见，MUST NOT 静默丢条目。
- FR-3.6 列举被拒（`EACCES` / `EPERM`）且该主目录为不可用状态时，MUST 就地显示原因与「重试」，MUST NOT 直接抛原始错误码。

### FR-4 新建文件夹

- FR-4.1 四主目录模式下提供「新建文件夹」按钮，弹出输入框，输入**单个目录段名称**。
- FR-4.2 默认名 `未命名文件夹` / `Untitled folder`；同级冲突时追加序号（`未命名文件夹 2`、`3`…）。
- FR-4.3 名称 MUST 在**服务端**再校验：拒绝空串、路径分隔符、`.` / `..`、控制字符；创建后重新列目录并选中新目录。
- FR-4.4 创建目标 MUST 落在当前主目录内（服务端按真实路径做包含性校验）；越界请求 MUST 被拒绝并返回可归因错误。
- FR-4.5 同名已存在 MUST 返回「已存在」类错误，UI 留在输入态并提示，MUST NOT 覆盖或静默成功。

### FR-5 选择与采纳

- FR-5.1 「打开/选择文件夹」采纳当前选中目录。
- FR-5.2 采纳值 MUST 是**绝对真实路径**，经既有 `onSelect(path)` 回传，复用上游 `createWorkspace` 采纳链路，不改采纳语义。
- FR-5.3 采纳前 MUST 校验被选路径落在当前主目录内（根围栏，§8）。
- FR-5.4 「取消」或关闭对话框 MUST 触发 `onSelect(null)`（沿用上游语义）。

### FR-6 授权

- FR-6.1 列举用户目录失败（`EACCES`/`EPERM`）时，先经插件 RPC 预检权限；未授权则在**对话框内**发起系统授权请求，
  按钮进入 loading 态。
- FR-6.2 授权回调为「已授权」后 MUST **重试一次全新的列举**，并**以列举是否成功作为唯一事实判据**（F8）；
  MUST NOT 只依赖 `CheckPermissions` 的返回值判定成功。
- FR-6.3 授权失败/拒绝时 MUST 展示原因 + 「去系统设置」入口（经 `ElectronApp.OpenApplicationInfoEntry` 深链到本应用信息页）；
  返回后用户可手动重试。
- FR-6.4 权限桥不可用（`electron` 不可达 / 无 active context / 回调非预期类型）时 MUST 明确归因提示，MUST NOT 静默失败、MUST NOT 假装成功。
- FR-6.5 权限相关**不改变全局状态**（不改插件树、不改权限声明面）；不新增权限声明。

### FR-7 主目录记忆

- FR-7.1 主目录选择持久化到渲染层 `localStorage`（插件私有键，带前缀）。
- FR-7.2 **只记忆主目录，不记忆子路径**：再次打开停留在该主目录根。
- FR-7.3 存储值非法（不属于四个主目录 id）时回退「沙箱」。
- FR-7.4 记忆值指向的主目录本次不可用时，回退「沙箱」并在 UI 明示，MUST NOT 静默停在不可用主目录。

### FR-8 装配与加载

- FR-8.1 能力插件为**壳专用** opencode 插件，目录名 = npm 包名 = 插件 `id` 前缀：`plugins/oc-plugin-workspace-roots/`。
  目录名 = npm 包名，符合 `plugins/README.md` §4 命名约定。
- FR-8.2 UI 改动以**上游补丁**（`patches/v2.0.26/0007-*.patch`）落地，MUST NOT 修改上游源码入库；
  补丁 MUST 幂等（可重复 `build-opencode.mjs` 而不冲突）、MUST 只增不改公共语义。
- FR-8.3 插件 MUST 满足 `plugins/` 准入条件（不依赖 PTY / 不 spawn / 不依赖原生模块）；MUST 通过 `collect-app.mjs` 的静态断言与投放校验。
- FR-8.4 四主目录模式 MUST 自门控：RPC 不可达时回退上游行为（FR-1.4），使补丁对**非本壳**的 `platform === "web"` 部署零影响。
- FR-8.5 沙箱主目录与既有工作区根（`<userData>/workspace`）MUST 为**同一取值**，不引入第二处真值来源。

## 6. 方案对比

| | A. 纯插件（无补丁） | B. 插件（能力）+ 最小补丁（UI）**（采用）** | C. 纯补丁（协议 + 服务端 + UI 全改） |
|---|---|---|---|
| 四主目录真实路径 | 插件 RPC ✅ | 插件 RPC ✅ | 改 `packages/server` 新增 HTTP 端点 |
| 新建目录 | 插件 RPC（`node:fs`）✅ | 插件 RPC ✅ | 新增协议组 + 重新生成客户端（codegen 风险） |
| 权限桥（只有主进程可达） | 插件 RPC ✅ | 插件 RPC ✅ | 服务端直连亦可，但需改协议 |
| 对话框 UI | ❌ **不可能**（上游插件无 UI 钩子，`gui-extensions` 不能拦截既有对话框，见 `#13`） | 最小补丁（四 Tab / 根围栏 / 新建 / 去手输路径） | 同 B，且额外改协议 |
| 改动面 | —（做不到） | 1 个插件 + 1 个补丁 + `main.js` 注入 | 插件 + 协议 + 服务端 + 生成客户端 + UI |
| codegen / 生成物风险 | 无 | **无**（复用已存在的 `rpc.call` 端点与生成客户端） | 有（`protocol/openapi.json` + `packages/client/src/promise/generated/*` 需重生成） |
| 上游升级 | — | 接缝稳定（`rpc.call` 是文档化端点；对话框是既有组件） | 协议漂移面更大 |

**结论：采用 B。** 依据 F4：能力（路径 / 建目录 / 权限）在服务端进程天然成立，用**插件机制**承载，零 codegen；
只有 UI 必须落补丁，且补丁保持最小、自门控。

## 8. 根围栏（安全属性）

选定主目录后浏览域被锁定，这是**安全属性，不是待修的 bug**：

1. 进入/切换主目录时，浏览视图的第一层锁为该主目录根的 `fs/list` 结果；展开只接受「当前层条目产生的子路径」。
2. 导航目标在进入前经 `isWithin(rootPath, target)` 判定；不满足则**忽略该次导航**（不改变视图，不报错炸栈）。
3. 四主目录模式下**没有手动路径输入**（FR-3.4），UI 层不存在提交任意绝对路径的入口。
4. 采纳前再判一次（FR-5.3）；服务端 `mkdir` 亦独立判一次（FR-4.4）——**UI 判定与后端判定各自成立**，不互为依据。
5. 主目录解析结果是后续操作唯一路径来源；切换主目录必须重置整视图。

四个主目录互为隔离浏览域：可向下自由穿越，不能上溯，不能横向越界。

> **性质披露（必须如实）**：`fs/list` 本身**不做**根限制（`#4`），因此根围栏是 **UI 层 + 插件层围栏**，
> 不是内核沙箱：绕过 UI 直接调 `fs/list` 仍可列举其它路径（与现状一致，非本模块新引入）。
> 本模块的目标是「让入口可用且边界清晰」，不是收紧既有 API 面；收紧属独立变更（见 §16 R6）。

## 9. 数据流

```
启动期
  configureEnvironment()   捕获真实家目录 → OCR_USER_ROOTS（三个用户主目录绝对路径）
                           HOME/USERPROFILE → userData（沙箱）
  ensureWorkspace()        <userData>/workspace（mkdir + chdir）
  materializePlugins()     resfile/.../plugins/oc-plugin-workspace-roots → <userData>/config/opencode/plugin/
  服务端启动 → 插件加载：context.rpc.register('oc-harmony-workspace-roots', {roots,mkdir,permission*,openAppInfo})

交互期
  点「打开项目」→ useDirectoryPicker().pickDirectory({ server, location, title, onSelect })
    → 应用内 DirectoryPickerDialog（platform==='web'，F1）
      ├ createResource: sdk.api.rpc.call({ rpcID, method:'roots', input:{} })
      │    ├ 成功 → 四主目录模式
      │    │    ├ 读 localStorage 主目录 id（默认 sandbox）
      │    │    ├ 渲染 RootsTabs；当前 root.path 作为浏览起点（无手输路径）
      │    │    ├ sdk.api.file.list({ location, path: <root.path 或子目录> }) → 树渲染
      │    │    │     被拒（EACCES/EPERM）→ PermissionGate
      │    │    │        ├ rpc 'permissionCheck' 已授权 → 视为瞬时错误，重试 list
      │    │    │        └ 未授权 → rpc 'permissionRequest'（loading）
      │    │    │              ├ 回调 0 → **重试全新 list**，成功即渲染（F8：事实判据是 list）
      │    │    │              └ 非 0/拒绝 → 原因 + 「去系统设置」（rpc 'openAppInfo'）
      │    │    ├ 新建文件夹 → 名称去重（UI）→ rpc 'mkdir' → 重列 → 选中
      │    │    └ 打开 → isWithin 校验 → onSelect(绝对路径) → 上游 createWorkspace
      │    └ 失败（未注册/404/不可达）→ 完整回退上游行为（FR-8.4）
```

## 10. 授权流程

```
fs/list 返回 EACCES / EPERM
        │
        ▼
rpc permissionCheck({id})  ── 已授权 ──► 视为瞬时错误，直接重试 list
        │  （插件 → systemPreferences.callArkTSAsyncFunction
        │    'PermissionManagerAdapter.CheckPermissions'）
      未授权
        ▼
rpc permissionRequest({id})   # id ∈ {desktop,documents,download}
        │  （插件 → ...'PermissionManagerAdapter.RequestPermissionCode'，ArkTS
        │     atManager.requestPermissionsFromUser；回调 0 = 授权成功）
        │  对话框进入 loading，取消其它操作
        ├ 回调 0 ────────► **重试全新 list**；成功即渲染（F8 明文要求：不单独信任 check 桥）
        ├ 非 0 / 拒绝 ───► 原因说明 +「去系统设置」（rpc openAppInfo →
        │                     'ElectronApp.OpenApplicationInfoEntry' → 本应用信息页
        │                     「文件和文件夹」）；返回后手动「重试」
        └ 桥不可用 / 无 active context ► 明确归因提示 + 重试（不静默、不假装成功）
```

权限类型映射（`web_engine/src/main/ets/adapter/PermissionManagerAdapter.ets:41-69`）：
`desktop → directory_desktop`、`documents → directory_document`、`download → directory_download`；**沙箱免授权**。

> 真机前置（F8，🔶 沿用）：该类 2-in-1 PC 模式 runtime 上主动申请可能**不弹窗且不改变实际访问**，
> 唯一生效面是系统设置里的「文件和文件夹」开关。因此 FR-6.2 把「列举成功」而非「check 返回 true」
> 作为事实判据；FR-6.3 的「去系统设置」是**必须存在**的兜底路径。本工程须真机复验并回写
> `docs/真机验证记录.md` 与 `docs/鸿蒙环境能力清单-v2.0.26.md`。

## 11. 错误处理

| 场景 | 表现 |
|---|---|
| 主目录不可用（不存在 / 非目录 / 解析失败） | 该 Tab 仍可见；内容区显示不可用说明 + 重试（FR-2.3），不回退其它主目录 |
| 列举被拒且未授权 | 走 §10；不把原始 `EACCES`/`EPERM` 直接抛给用户 |
| 列举被拒但已授权 | 视为瞬时错误，就地提示 + 重试，不关闭对话框 |
| 新建目录名非法 | 服务端返回可归因错误；UI 留在输入态并提示 |
| 新建目录同名 | 返回「已存在」类错误；UI 提示冲突，留在输入态（FR-4.5） |
| 新建目录越界 | 服务端拒绝（FR-4.4）；UI 提示越界，不创建 |
| 采纳失败（上游工作区创建失败） | 复用上游错误 Modal（含重试），与现状一致 |
| 四主目录能力不可用 | 完整回退上游对话框（FR-8.4），不出现半残状态 |
| 桥不可用 / 无 active context | 明确归因提示（FR-6.4），不静默 |

浏览类失败在对话框自有区域内消化，**不驱动**上游 owner 的错误链路之外的全局状态；
采纳阶段的错误仍走上游既有错误链路（对齐上游语义）。

## 15. 约束与已知限制

- 只面向**四个主目录**：不提供整盘浏览，不恢复手动路径输入（FR-3.4）。
- **范围决策（评审意见 #3，已确认接受）**：四主目录替换对本工程**所有**目录选择入口生效
  （上游 `useDirectoryPicker()` 的 5 个调用方：首页/侧栏添加项目、设置内项目列表、会话内「选择另一个目录」、
  新建会话选项目、扩展 API）。因此**手动路径输入被移除**（FR-3.4 的直接后果），且浏览域限定在四个主目录内。
  由此带来的已知边界：**沙箱主目录 = `<userData>/workspace`**（与宿主 `ensureWorkspace()` 同值，FR-203-003/8.5），
  因此**位于 `<userData>` 下、但不在 `workspace/` 内**的既有目录（例如未来的 `<userData>/projects`）无法再被选中。
  若未来需要「只对添加项目入口启用四主目录、其它入口保留手输路径」，做法是在入口侧显式订阅
  （如 `useDirectoryPicker({ rootsOnly: true })`），属**独立变更**，见 §18。
- 三个用户目录的可用性以「OS 层授权 + `specs/006` 声明的权限」为前提；`Desktop` 属 `system_basic`（需 ACL），
  未获批则桌面主目录不可用，**不影响**沙箱 / 文档 / 下载。
- 根围栏是 UI + 插件层围栏，非内核沙箱（§8 性质披露）。
- 搜索/建议通道（`fs/find`）在目标平台不可用；四主目录模式下不依赖它，逐级展开是预期路径（F3）。
- 不依赖 `ContextPathAdapter.getUser*Dir`（当前为空实现，`#12`）；若未来改用系统 API 取路径，
  需补 ArkTS 实现 + 绑定，并把它登记进 `collect-runtime.mjs` 的 overlay/改写规则（属独立变更）。
- 仅支持选择目录，不支持文件选择、多选、重命名、删除。
- `RequestPermissionCode` 在同类 PC runtime 上可能「返回成功但不弹窗」（F8，🔶 沿用）：
  该情形下授权只能经系统设置完成，「请求授权」按钮属**尽力而为**；FR-6.3 的入口是必需兜底。

## 16. 风险与遗留

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 插件 RPC 在真机不可用（插件未加载 / 定义校验失败 / `Plugin.awaitActivation` 时序） | 四主目录模式不出现（回退上游，不崩） | AC-10 用 `--inspect` 直接调 `rpc.call` 定论；启动日志 `loading plugin` + inventory 状态 |
| R2 | 品牌化后置断言（37 项）因 `packages/app` 改动硬失败 | 构建中止 | AC-12；断言与引用点漂移按 `scripts/verify-branding.mjs` 提示同步更新，不绕过 |
| R3 | 真机用户目录实际不可读（授权面与 dsh 结论一致：只能走系统设置） | 桌/文档/下载不可用 | FR-6.3「去系统设置」兜底；沙箱路径独立可用；结论回写能力清单 |
| R4 | 真实家目录捕获时机错误（`HOME` 已被上游改写） | 三个用户主目录解析失败（标记不可用，不静默） | 在 `configureEnvironment()` 覆盖前捕获 + 逐项 `existsSync` 校验 + trace 落盘（FR-2.4） |
| R5 | `inprocess` 之外的宿主形态（`utility` / `worker`）下 `electron` 不可达 | 权限桥失效（RPC 明确报错） | 与 `specs/007-runtime-host` 的默认与真机形态一致（`inprocess`）；桥不可用时 FR-6.4 归因可见 |
| R6 | 根围栏可被绕过（直接调 `fs/list`） | 与现状同风险，本模块未扩大 | §8 性质披露；若需收紧，单列模块改造 `fs/list`（独立变更） |
| R7 | 上游升级后 `rpc.call` 端点或对话框结构变化 | 补丁冲突 / 门控失效 | 补丁幂等 + `--reverse --check` 前置；升级时随对应上游 tag 复验（与本工程 005 流水线同口径） |
