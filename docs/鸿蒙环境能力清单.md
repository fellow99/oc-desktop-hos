### 1.2 根因分层（L1–L4）

| 层 | 性质 | 可恢复性 | 本工程典型项 |
|---|---|---|---|
| **L1 平台硬约束** | 鸿蒙产品策略 / 权限体系 / SELinux / seccomp | 难；部分**不可上架** | PTY、应用域子进程 JIT、用户目录 ELF 执行、`symlink` / `hardlink` / `chmod` 语义、loopback 隔离、子进程退出不可观测、Desktop 目录权限、开机自启 |
| **L2 原生产物缺失** | 上游/框架的原生构件与平台不匹配 | 交叉编译或替换可恢复，但受 L1 封顶 | 无 ohos 版 `node-pty`、`@ff-labs/fff-node`、无 `node:sqlite` binding、数万小文件入 HAP 不可行 |
| **L3 本工程配置选择** | 由本工程决定的取舍（不是平台限制） | 改配置即可，成本最低 | 宿主形态、渲染通道、文件监听关闭、`fff` 关闭、模型抓取关闭、插件档位 |
| **L4 上游接口缺口** | 上游没有对应接口/变体 | 需自研、补丁或另案 | 非 PTY 命令执行后端、纯 JS 搜索变体、插件硬开关、目录选择器 |

### 1.3 三个「会骗人的探针」（观测点必须选对）

| 探针 | 假结论 | 正确口径 |
|---|---|---|
| `readlink /proc/self/exe` | 报 `/system/bin/toybox`，据此会误判 shell 身份 | ❌ 勿用；shell 身份用 `KSH_VERSION` + `md5sum` 比对判定（D ✅：`/system/bin/sh` = mksh R59） |
| `uname -a` 尾部 `Toybox` | 看似说明当前 shell 是 toybox | ❌ 那是**内核 build-time utsname 字符串**，与当前进程无关 |
| `hdc shell ls /data/service/hnp` | 看起来整个 HNP 树不存在（`No such file or directory`） | ❌ SELinux 在 `sh` 域（`u:r:sh:s0`）**隐藏**该路径；应用域可见（`/data/service/hnp/bin/node` 存在且 `X_OK`）。**凡涉及该路径与权限的结论，一律以应用域为观测点** |

> 推论：本工程所有平台结论 MUST 在**应用域**（宿主进程内 / `--inspect` / hilog）取证，`hdc shell` 的结果只能作为辅助证据。

## 2. 能力主表

> 状态列：✅ 实测通过 ｜ ⚠️ 受限 / 部分可用 ｜ ❌ 不可用 ｜ ⬜ 未验证。
> 「本工程」列给出该能力对 opencode v2 落地的处置与阻塞关系。

| # | 能力 | 状态 | 根因层 | 事实与处置 | 来源 → 本工程 |
|---|---|---|---|---|---|
| 1 | `fork` + `execve` + 管道 + PATH 查找 | ✅ | — | 放行；`/system/bin/sh`、`/bin/sh`、`/system/bin/toybox` 均可 spawn 并取回正确 stdout | **D** ✅ → ⬜ 复验（命令执行路线的前提） |
| 2 | **应用域 fork+exec 出的 node 脚本** | ❌ | **L1（seccomp）** | `node -e …`、`node x.js`、`node --jitless -e`、`npm -v` → **`Signal 31 (core dumped)`（SIGSYS）**；而 `node -v` / `--v8-options` 正常、`python3 -c` 正常 ⇒ **子进程无法分配 JIT 可执行内存**；`danger-full-access` 后不变（非文件沙箱） | **D** ✅ → ⬜ 复验（决定宿主形态：服务端 MUST NOT 跑在「应用域 fork 出的 node」里） |
| 3 | PTY / 终端 | ❌ | **L1** | SELinux 拒 `forkpty` / `openpty` / `posix_openpt` / `popen`（`EACCES`）；无官方应用级 API | **D** ✅ + 官方 NDK 受影响清单 → ⬜ 复验（`#pty` / `#persistent-pty-binary` 打桩；不做终端面板） |
| 4 | 用户目录 ELF 执行 | ❌ | **L1** | `/storage/Users`、el2 数据目录不可 exec；可 exec 的 `/data/service/hnp/bin`、`/data/app/bin` 不可写；自有 ELF 需 **AGC 二进制证书（`certType: 4`）**，个人主体不可得 | **D** ✅ → ⬜ 复验（不随包分发并执行自有 ELF；`rg` / `git` 不可用） |
| 5 | `symlink` | ❌ 应用域 / ✅ shell 域 | **L1** | 应用域 `EACCES`（错误码 `13900012`）；shell 域（`u:r:sh:s0`）`ln -s` **成功** ⇒ 禁令**按 SELinux 域生效**，只作用于应用域 | **D** ✅ → ⬜ 复验（一律 **copy 物化**，禁依赖 symlink） |
| 6 | `hardlink` | ❌ | **L1** | hmdfs 无 `.link` 处理器 → `EPERM` / `Permission denied`；**shell 域同样被拒** | **D** ✅ → ⬜ 复验（原子写只走 `rename`，禁用 link 分支） |
| 7 | `chmod` | ⚠️ 静默不落实（hmdfs）/ ✅ 如实（hmfs） | **L1** | 不报错但请求的 mode 不被落实：请求 `600`/`644`/`640` → 回读恒 `660`；请求 `755` → 回读 `770`；工作区（`hmfs`）如实回读 | **D** ✅ → ⬜ 复验（**写入后回读校验**，不一致即报错，不得伪装成功） |
| 8 | `Documents` / `Download` / `Desktop` 直写 | ⚠️ | **L1** | 目录 `mode 2771`、属主 `file_manager`（uid 20001006 / gid 1006），应用 uid 落 "other"（仅 `--x`）⇒ 未授权时 `R_OK`/`W_OK` = `EACCES`、`writeFile`/`mkdir` = `EPERM`；须在「设置 → 应用 → 本应用 → 允许访问」授权并**重启应用**；`Desktop` 权限为 `system_basic`（上架障碍） | **D** ✅ → ⬜ 复验（见 `specs/011-workspace-auth/`、`docs/ACL申请清单.md`） |
| 9 | loopback（渲染进程访问 `127.0.0.1`） | ❌ | **L1** | 进程间网络隔离拦截 ⇒ 服务端必须绑 `0.0.0.0` + 用局域网 IP 加载；R1（Chromium）需配合 `Host`/`Origin` 头改写，R2（ArkWeb）是否仍需改写待探针 | **D** ✅ + **H** 🔶 → ⬜ 复验（P0-2 渲染通道探针） |
| 10 | 子进程退出可观测性 | ❌ | **L1** | 事件序列只有 `proc:spawn → stdout:end → stderr:end → stdout:close`，**永无 `proc:exit` / `proc:close`**；`/proc/<pid>/stat` = `Z`；`cp.exec` **永不回调**；每次 spawn 净 +1 僵尸（实测 4 spawns → 4 zombies，单会话累计 30 个挂主进程 pid） | **D** ✅ → ⬜ 复验（常驻单 shell + 哨兵行；见 `specs/010-tool-shell/`） |
| 11 | `worker_threads` | ✅ | — | `new Worker()` 可在进程内跑 CLI（dsh 用其跑 pnpm）；**JIT 可用、无需证书、无需新权限、`process.exit` 只退 worker**；限制：worker 内不能 `process.chdir` | **D** ✅ → ⬜ 复验（宿主候选 C） |
| 12 | 托盘 / 状态栏图标 | ✅ **仅 2in1** | — | `statusBarManager` + `StatusBarViewExtensionAbility`（`@kit.DeskTopExtensionKit`，旧名 `@kit.StatusBarExtensionKit` 已 deprecated）；**无运行时权限要求**；右键菜单「退出」由平台自带 | **D** ✅ → ⬜ 复验（Phase 2/3，视上架要求） |
| 13 | 后台常驻 / 开机自启 | ⚠️ / ❌ | — / **L1** | **2in1 最小化不构成后台**：最小化后 `aa dump -a` 仍为 `state #FOREGROUND`（窗口变 `WINDOW_OCCLUDED(5)`），`onBackground` **从不触发**，长时任务代码路径实际未被执行；`autoStartupManager` **只有只读接口**（无公开 setter），第三方亦无 `BOOT_COMPLETED` 静态订阅 | **D** ✅ → ⬜ 复验（不做后台常驻承诺；退出即退出） |
| 14 | 无可见窗口常驻 | ✅ 2in1 / 平板 | — | `ProcessMode.ATTACH_TO_STATUS_BAR_ITEM` / `NEW_PROCESS_ATTACH_TO_STATUS_BAR_ITEM` + `StartupVisibility.STARTUP_HIDE`（API 12+），配合 `hideAbility()` / `showAbility()` | **D** ✅（官方文档口径）→ ⬜ 复验 |

| 17 | `homedir()` | ⚠️ | **L1** | `homedir()` = `/storage/Users/currentUser` **不可写**；应用沙箱 `userData` = `/data/storage/el2/base/files`（**`hmfs`**）可写 | **H** 🔶 + **D** ✅ → ⬜ 复验 |

## 4. 与上架合规的关系（不重复 `docs/ACL申请清单.md`，只给能力侧结论）

| 能力事实 | 上架含义 |
|---|---|
| ArkWeb 可用且能承载 Web UI（#20） | 满足「应用渲染打开网页时须使用 ArkWeb 组件」的审核口径；R1（Chromium）需按此整改 |
| 用户目录 `Desktop` 为 `system_basic`（#8） | 若声明该权限即构成上架障碍 ⇒ **不声明**，代价是失去桌面目录直写 |
| 自有 ELF 需二进制证书（#4） | 不随包分发并执行自有 ELF ⇒ 不需要二进制证书，也不需要 `ALLOW_EXTERNAL_NATIVE_CODE` |
| 子进程以应用 uid 运行、无内核沙箱（#10、#27） | shell 工具必须在工具层自建围栏并如实披露「可被绕过」；不得描述为沙箱 |
| AI 生成内容 | 界面须有常驻标识（不属能力边界，属产品合规） |
