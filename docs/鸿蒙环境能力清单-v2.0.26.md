### 1.5 根因分层（L1–L4，沿用 v0.1 不变）

| 层 | 性质 | 可恢复性 | 本工程典型项 |
|---|---|---|---|
| **L1 平台硬约束** | 鸿蒙产品策略 / 权限体系 / SELinux / seccomp | 难；部分**不可上架** | PTY、应用域子进程 JIT、用户目录 ELF 执行、`symlink`/`hardlink`/`chmod` 语义、loopback 隔离、子进程退出不可观测、Desktop 目录权限、开机自启 |
| **L2 原生产物缺失** | 上游/框架的原生构件与平台不匹配 | 交叉编译或替换可恢复，但受 L1 封顶 | 无 ohos 版 `node-pty`、`node:sqlite` 无 binding、**`rg` 无 `arm64-ohos` 平台键**、数万小文件入 HAP 不可行 |
| **L3 本工程配置选择** | 由本工程决定的取舍（不是平台限制） | 改配置即可，成本最低 | 宿主形态、渲染通道、文件监听关闭、模型抓取关闭、插件档位 |
| **L4 上游接口缺口** | 上游没有对应接口/变体 | 需自研、补丁或**插件** | 非 PTY 命令执行后端、纯 JS 搜索变体、插件硬开关、目录选择器 |

### 1.6 三个「会骗人的探针」（沿用 v0.1，本轮补一条）

| 探针 | 假结论 | 正确口径 |
|---|---|---|
| `readlink /proc/self/exe` | 报 `/system/bin/toybox`，据此误判 shell 身份 | ❌ 勿用；shell 身份用 `KSH_VERSION` + `md5sum` 判定 |
| `uname -a` 尾部 `Toybox` | 看似说明当前 shell 是 toybox | ❌ 那是**内核 build-time utsname 字符串** |
| `hdc shell ls /data/service/hnp` | 看起来 HNP 树不存在 | ❌ SELinux 在 `sh` 域隐藏该路径；**凡涉及该路径与权限的结论一律以应用域为观测点** |
| **（本轮新增）** `hdc shell cat <userData>/<file>` | 报 `Permission denied` ⇒ 误判「应用写不出这个文件」 | ❌ 那是**文件 mode 0600** 与 shell 域 uid 不同所致；判定「应用能否读写」必须用**应用域探针**，`sh` 域只能看目录列举 |

## 6. 有哪些能力可以用 JS 插件代替（需求明确要求的分析）

完整规格见 [`specs/102-harmony-js-tools/spec.md`](../specs/102-harmony-js-tools/spec.md) §3。

| # | 缺口（对应 §2 的条目） | 根因层 | 可否 JS 替代 | 判定依据 |

| G1 | `shell` 命令执行（#1 #10） | L1（子进程退出不可观测） | ✅ **可** | 上游 `shell` 用 cross-spawn（纯 JS → `node:child_process`），启动本身可用；但设备上**永不触发** `exit`/`close`、`cp.exec` 永不回调 ⇒ 工具挂死。改为「常驻 `/system/bin/sh` + 随机哨兵行」，把「结束」判定从进程事件改为 **stdout 哨兵**，纯 JS 即可完成 |

### 6.1 与参考实现的对应关系

本工程的替代方案**不是凭空的**：`dsh-desktop-hos` 的 `plugins/` 与 `pi-desktop-hos` 的
`specs/102-harmony-js-tools/` 已在同型设备上验证过同一思路（非 PTY 常驻 shell + 哨兵、纯 JS 搜索）。
差异在于**宿主契约不同**：

| 维度 | `dsh-desktop-hos` 插件 | `pi-desktop-hos` 扩展 | **本工程（opencode v2）** |
|---|---|---|---|
| 注入形态 | dsh 插件 + preset 行（`harmony-plugin-XXX`，**编译期打进 HAP + 运行期 copy 到 profiles**） | pi 自动扫描 `extensions/` 目录（单文件，无 `package.json`） | **opencode 插件**：默认导出 `{ id, setup }`，用 `context.tool.transform(editor => …)` 覆盖工具 |
| 工具名 | `bash` / `grep` / `glob` / `delete` / `move` / `copy` / `chmod` | `bash` / `grep` / `find` | `shell`（注意**没有** `bash`）/ `grep` / `glob` |
| 发现目录 | `$DSH_HOME/profiles/node_modules/` + preset 行 | `pi-dist/resources/pi-agent/extensions/` | **配置目录下的 `plugin/`**（本工程 = `<userData>/config/opencode/plugin/`，由 `XDG_CONFIG_HOME` 决定） |
| 覆盖键 | 包名 + preset 行 | 工具名 | **工具有效名**（`shell`/`grep`/`glob`）+ 插件 id（`opencode.tool.*`）双写 |
| 物化 | copy（禁 symlink） | copy（禁 symlink） | copy（禁 symlink，`materializePlugins()`） |
