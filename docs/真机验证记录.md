# 真机验证记录（oc-desktop-hos）

> **版本**：v0.1（首版）｜ **日期**：2026-10-11 ｜ **适用工程**：`oc-desktop-hos`（OC Desktop / `org.fellow99.oc.OCDesktop`）
> **用途**：每轮真机验证的**环境、步骤、结论与原始证据**的唯一落点；Phase 0 的三个矩阵（P0-1 / P0-2 / P0-3）在本文件内**待填**。
> **上游基线**：opencode `v2.0.26` ｜ **运行期**：Electron 37（`v37.2.3-20260825.1` = Node 22.17.0 / Chromium 138 / ABI v138）。
> **纪律（硬性）**：
> 1. **禁止编造实测**。未执行的条目一律保留状态 `⬜ 待验证`；不得以「应该可以」代替证据。
> 2. 每条记录必须齐备四列：**结论 / 证据 / 日期 / 设备**。
> 3. **一切以应用域为观测点**（`hdc shell` 视角可能骗人）：`/data/service/hnp` 在 `sh` 域被 SELinux 以 ENOENT 隐藏，应用域却可见；`readlink /proc/self/exe` 会误报 `/system/bin/toybox`；`uname -a` 的 `Toybox` 是内核字符串。
> 4. 探针的**失败证据与成功证据同等重要**：失败必须原样记录（含 stdout/stderr 与错误码）。
> 5. 结论一旦写入，必须同时回写受影响的规格（`specs/010-tool-shell/`、`011-workspace-auth/`、`012-data-dirs-sqlite/`、`201-plugin-runtime/`）与 `docs/鸿蒙环境能力清单.md` 的标注（⬜ → ✅）。

**本轮真机发现、已修复并在真机复验的 4 个缺陷**（宿主单测当初没覆盖到）：

1. **非快进合并后工作树未检出**（严重：合并成功但索引/工作区与 HEAD 不一致，`git_status` 报 `D <file>`）。修法：合并成功后统一按当前分支 `checkout(force)`，并加脏树守卫。
2. **`git_reset --hard` 把 HEAD 变成游离**。修法：按分支名检出（oid 检出会写游离 HEAD），已加回归断言。
3. **`git_cherry_pick` 建了提交却回显 `no new commit`**（库返回 oid 字符串，按 `result.oid` 读不到）。修法：按字符串读取并回填 metadata。
4. **`git_cherry_pick` / `git_revert` 只吃完整 40 位 oid**（分支名、短哈希都失败）。修法：新增 `resolveCommitish()`（先 `expandOid` 再 `resolveRef`），与原生 git 行为对齐。

第二轮（带账号内网仓库）又发现 2 个缺陷，同样已修并真机复验：

5. **`git_pull` 在「本来就没事可做」的仓库上抛 `MissingNameError`**：isomorphic-git 的 pull 内部走 merge，即使只快进也要 author/committer。修法：pull 显式传身份，并在 pull 成功后按当前分支补一次 `checkout(force)`（与 merge 同源的工作树不同步问题）。
6. **`git_branch action list remote true` 恒返回空**：isomorphic-git 的 `listBranches` 要的是**远端名**，我们把布尔 `true` 直接传了下去。修法：`true` 解析为 `origin`，也支持显式远端名字符串；列远端时不打「当前分支」标记。

设例 12 例（新增远端跟踪分支列表），`verify-git-plugin` 现为 **33 pass / 0 fail / 2 skipped**。
