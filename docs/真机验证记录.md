# 真机验证记录（oc-desktop-hos）

> **版本**：v0.1（首版）｜ **日期**：2026-10-11 ｜ **适用工程**：`oc-desktop-hos`（OC Desktop / `org.fellow99.oc.OCDesktop`）
> **用途**：每轮真机验证的**环境、步骤、结论与原始证据**的唯一落点；Phase 0 的三个矩阵（P0-1 / P0-2 / P0-3）在本文件内**待填**。
> **上游基线**：opencode `v2.0.26` ｜ **运行期**：Electron 37（`v37.2.3-20260825.1` = Node 22.17.0 / Chromium 138 / ABI v138）。
> **纪律（硬性）**：
> 1. **禁止编造实测**。未执行的条目一律保留状态 `⬜ 待验证`；不得以「应该可以」代替证据。
> 2. 每条记录必须齐备四列：**结论 / 证据 / 日期 / 设备**。
> 3. **一切以应用域为观测点**（`hdc shell` 视角可能骗人）：`/data/service/hnp` 在 `sh` 域被 SELinux 以 ENOENT 隐藏，应用域却可见；`readlink /proc/self/exe` 会误报 `/system/bin/toybox`；`uname -a` 的 `Toybox` 是内核字符串。
> 4. 探针的**失败证据与成功证据同等重要**：失败必须原样记录（含 stdout/stderr 与错误码）。
> 5. 结论一旦写入，必须同时回写受影响的规格（`specs/010-tool-shell/`、`011-workspace-auth/`、`012-data-dirs-sqlite/`、`201-plugin-runtime/`）与 `docs/鸿蒙环境能力清单.md` 的标注（⬜ → ✅）。

### 1.3 证据规范

| 类型 | 取证方式 | 备注 |
|---|---|---|
| 应用日志 | `hdc shell "hilog -x \| grep oc-desktop"` | 统一前缀 `[oc-desktop]`；阶段化 loading 页文本亦可截图 |
| 进程内观测 | CDP：`hdc fport tcp:19229 tcp:9229` + `Runtime.evaluate` | **仅 debug 构建**；生产构建必须移除 `--inspect`（默认带）与 `remote-debugging-port` |
| 文件与权限 | 应用域内 `existsSync` / `statSync` / 写入回读探针 | **不要**用 `hdc shell` 的 `ls` / `stat` 判「应用能否访问」 |
| 僵尸与进程 | `/proc/<pid>/stat`（应用域读取）、`ps` | 退出事件不可观测，僵尸计数是主要指标 |
| 截图 | `hdc shell snapshot_display -f /data/local/tmp/...` 或 UI 截图 | 首屏/白屏类结论必须附截图 |

## 3. P0-1 宿主形态矩阵（三候选 × 五项）

**候选**：**A** = `utilityProcess.fork(sidecar.js)` 内 `import` bundle 并 `serve`；**B** = 主进程进程内 `import` bundle 并 `serve`；**C** = 主进程内 `new Worker()` 跑 bundle。

|---|---|---|---|---|---|
| ① | JS/JIT 示性 | `new Function` + 计算密集递归正常返回；**不出现** `Signal 31 (SIGSYS)` | ⬜ 结论／证据／日期／设备 | ⬜ 结论／证据／日期／设备 | ⬜ 结论／证据／日期／设备 |
| ② | 异步 `spawn("/system/bin/sh",["-c","echo hi"])` | stdout 取回 `hi`；**分别记录**是否出现 `exit` / `close` 事件（预期：只有 `stdout:end` / `close`） | ⬜ 结论／证据／日期／设备 | ⬜ 结论／证据／日期／设备 | ⬜ 结论／证据／日期／设备 |
